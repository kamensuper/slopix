LIMITATIONS
Use F12 or display WIDTH HEIGHT. Dragging the host QEMU window alone does not
request a new guest mode. No host-window autoresize/guest-agent protocol is added.
Runtime modes target QEMU PCI std VGA on PC bus 0; no native GPU-driver claim.
Supported explicit modes are bounded by existing 1920x1080 graphics buffers.
No persistent resolution settings, Settings app, FileSlop or FAT32 changes.
No sustained performance guarantee at every mode; see PERFORMANCE-0.8.md.

EXPLORATORY FAILURES AND FIXES
A test mouse driver initially kept coordinates outside the shrunken guest; it
now accounts for cursor clamping and tests real clicks after transitions.
An early multi-app audio run reported one underrun. Mixer checkpoints were
added between main-thread compositor/app tasks. Subsequent gameplay and final
resize/audio runs passed the unchanged zero-underrun requirement. Early serial
evidence is retained in build/early-0.8/audio-underrun-before-checkpoints.log.
One exploratory WAV capture lacked a finalized header despite zero guest faults.
A short diagnostic capture and subsequent complete gameplay captures passed.
The guest driver now also checks the QEMU process exit code. This does not prove
host backend/exit intermittency is permanently fixed.

PRESERVATION
