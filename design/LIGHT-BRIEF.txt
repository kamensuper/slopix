**Windows Vista Aero + Haiku OS.**

# M3 — Remove the FAT32 Limitations

**Priority: CRITICAL**

The earlier Slopix 0.9 filesystem implementation was limited to:

- Root-directory operations.
- FAT32 8.3 filenames.
- Files no larger than 64 KiB.

These restrictions must be addressed.

## Large-file support

Implement offset-based, bounded-buffer FAT32 reading and writing.

Support:

- Multi-cluster files.
- Fragmented cluster chains.
- File extension.
- Partial-sector writes.
- Partial-cluster writes.
- Correct file-size metadata.
- Cluster allocation and release.
- Safe EOF handling.
- Overflow checks.
- Disk-full errors.
- Corrupted FAT-chain detection.

Do not simply replace a 64 KiB static buffer with a larger static buffer.

The filesystem must support files larger than available contiguous kernel memory.

Target multi-megabyte files and substantially larger files where the disk and implementation permit.

Respect FAT32's actual maximum file-size limits.

## Directory support

Implement:

- Nested directory navigation.
- Directory creation.
- Directory deletion.
- Parent-directory navigation.
- Path parsing.
- Directory entry management.
- Correct `.` and `..` behavior.

## Long filenames

Implement VFAT long filename support if feasible.

Preserve 8.3 compatibility.

Validate long filename records, checksums, and malformed sequences.

## File operations

Support:

- Create.
- Read.
- Write.
- Append.
- Copy.
- Move.
- Rename.
- Delete.

Expose consistent APIs to FileSlop, Terminal, and userspace.

## Storage safety

Investigate the historical intermittent ATA-offline failure.

Preserve existing dirty-volume and write-failure protections.

Test all destructive filesystem operations against disposable copies of the persistent disk.

Do not claim crash-atomic writes or journaling unless implemented and verified.

**Acceptance:** Files larger than 64 KiB and nested directories work correctly, including across cold boots, without corrupting existing data.
